# Data-source parity sweep — consolidated findings (2026-10-14, read-only)

Method: `audit` skill, data-source dimension. Backend contract read first (`backend-contract.md`), then three per-surface
traces (`sweep-web.md`, `sweep-ios.md`, `sweep-android.md`), then every load-bearing claim below was re-read first-hand
in the file cited (or reproduced: the web date shift was run under `TZ=America/Vancouver`). Paths: web = `apps/web/src/`,
iOS = `apps/ios/RaSi-Fiters-App/`, Android = `apps/android/app/src/main/java/com/app/rasifiters/`, BE = `apps/backend/`.

Severity: **H** = same user, same moment, materially different number/date across surfaces · **M** = visibly different
rounding/scope/rank or a silently different data set · **L** = cosmetic / latent / dead UI.

## 2. Can-never-vary (b) — consolidated

1. **P-2** "N active / N total members" — all three surfaces, BE `programService.js:42-43,70-71`. (The only true ratio-of-equals left after the bar fix.)
2. **PR-1** Program-tab "Active Members" = enrolled count (== `total_members`).
3. **S-11** mobile DAILY AVERAGE after integer rounding (0/1).
4. **M-3** "Current streak" cannot fall to 0 (BE).
5. **S-6** `change_pct` sticks at +100.0 / 0.0 whenever the previous month is empty (BE `queryHelpers.js:13-18`).
6. **M-4** web diet "N.0"; `total_hours ?? total_duration/60` fallback never runs (all three); `is_active` filters; dead empty states (X-4).
7. `members.at_risk` / `top_performers` / `totals.*` of `/analytics/summary` — computed server-side, displayed nowhere (X-1).

## 3. Plan shape (full text is the ExitPlanMode plan)

- **Batch A — client-only, no backend deploy, live-binary safe:** S-4, S-7, S-9, S-10, S-11, S-12, M-1, M-4, M-5, M-6, L-1, L-3, X-3.
- **Batch B — one source for program progress:** additive `elapsed_days` + `total_days` on `GET /programs` (BE first), then web/iOS/Android read `progress_percent` + those two fields on Summary and the Program tab; web and iOS stop calling `/analytics/summary`; Android re-reads the program row after edit/refresh. Old binaries ignore the new fields; new clients fall back to the current client formula when a field is absent.
- **Decisions for the user (not changes):** D1 progress source A (server, recommended) vs B (all-client, same UTC-day formula); D2 meaning of "PTD MP %"; D3 what replaces "N active / N total"; D4 change-badge window semantics (BE); D5 current-streak anchoring (BE).
